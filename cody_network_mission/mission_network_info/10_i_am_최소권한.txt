1. AWS IAM
    1-1. IAM은 AWS 리소스에 대한 인증과 권한을 관리하는 서비스입니다.
    1-2. EC2: 웹 서버를 실행하는 가상 컴퓨터, S3: 이미지와 파일을 저장하는 스토리지, RDS: 데이터베이스를 운영하는 서비스
        => 모든 권한을 주고 싶지 않을 떄 IAM을 사용합니다.
    1-3. 인증(Authentication)
        => 지금 AWS에 접근하려는 사람이 누구인가?
    1-4. 인가(Authorization)
        => 이 사용자가 요청한 작업을 수행할 권한이 있는가?


2. AWS IAM 사용자(User)
    => IAM 사용자는 하나의 AWS 계정 안에서 생성하는 개별적인 사용자 신원입니다.

    2-1. IAM 사용자 AWS에 접근하는 방법
        접근 방법	                인증 방식	              사용 예시
        AWS Management Console	  비밀번호, MFA 등	        웹 브라우저로 AWS 관리
        AWS CLI 또는 SDK	       액세스 키 등 자격 증명	    명령어나 프로그램으로 AWS 작업 수행


3. Root 사용자와 IAM 사용자의 차이
    구분	    Root 사용자	                  IAM 사용자
    생성	    AWS 계정 생성 시 존재	        별도 생성
    권한	    계정에 대한 매우 광범위한 권한	    정책에 따라 제한
    주된 용도	 루트 전용 계정 관리 작업	        별도 사용자 신원이 필요한 작업
    보안 원칙	 일상적 사용 금지	필요한          권한만 부여


4. IAM 정책
    4-1. IAM 정책은 어떤 작업을 어떤 리소스에 수행할 수 있는지를 정의한 규칙 문서입니다.
    4-2. AWS에서는 일반적으로 JSON 형식으로 표현합니다.
    4-3. 예시
    {
    "Version": "2012-10-17",
    "Statement": [
        {
        "Effect": "Allow",
        "Action": "s3:GetObject",
        "Resource": "arn:aws:s3:::my-bucket/*"
        }
    ]
    }
        => Version : IAM 정책 언어의 버전, 정책을 해석하는 데 사용하는 언어 버전
        => Statement : 실제 권한 규칙들을 정의하는 부분
        => Effect : 해당 작업을 허용할지 거부할지 결정 / AWS IAM의 중요한 기본 원칙은 명시적으로 허용되지 않은 작업은 기본적으로 거부
        => Action : 허용하거나 거부할 작업을 지정
        => Resource : 권한을 적용할 AWS 리소스를 지정


5. IAM Role
    5-1. AWS 계정을 만들고 EC2 서버와 S3 저장소를 만들었다고 가정
        => AM User hong에게 다음과 같은 권한 (EC2 서버 조회 가능, EC2 서버 시작 및 중지 가능, S3에 파일 업로드 가능)
        => hong이라는 사용자 신원으로 AWS에 인증하고, 해당 권한을 사용해 작업을 수행할 수 있습니다.
    
    5-2. EC2 서버 자체도 AWS 리소스를 사용해야 한다면
        => Node.js로 웹 서버 프로그램을 만들었다고 가정
        => 이 프로그램은 EC2에서 실행되고 있습니다.
        => 사용자가 프로필 사진을 업로드하면 EC2에서 실행 중인 Node.js 프로그램이 S3에 파일을 저장해야 합니다.
        => AWS 입장에서는 EC2에서 실행되는 프로그램이라고 해서 S3에 접근할 권한을 자동으로 주지 않습니다.
        => S3 API를 호출할 때도 AWS는 다음 사항을 확인
            -> 요청을 보내는 주체는 누구인가? / 그 주체에게 S3에 파일을 업로드할 권한이 있는가?
    
    5-3. EC2 프로그램은 자신이 AWS 리소스에 접근할 권한이 있다는 사실 증명
        => IAM User의 액세스 키를 이용
        => IAM User를 만들고 S3 업로드 권한을 부여한 다음, 액세스 키를 EC2 프로그램에 제공하는 방법입니다.
        => 프로그램이 장기 액세스 키를 보관하고 관리해야 한다는 것
        => 키가 유출되면 공격자가 해당 IAM 사용자의 권한을 악용할 수 있고, 키 교체와 관리도 직접 신경 써야 합니다.
        => 더 안전한 방법 -> IAM Role
    
    5-4. IAM Role info
        => IAM Role: S3UploadRole
        => 부여된 권한: s3:PutObject
        => 허용된 리소스: my-bucket/images/*
        => 이 IAM Role은 S3의 특정 경로에 파일을 업로드할 수 있는 권한을 가지고 있습니다.
        => 이 역할을 EC2 인스턴스에 연결
        => IAM Role 자체가 권한을 가지는 AWS 신원
        => EC2 연결된 역할을 통해 임시 자격 증명을 제공받아 사용할 수 있습니다.
        => EC2에서 실행되는 프로그램은 그 임시 자격 증명을 사용해 S3에 요청할 수 있습니다.
    
    5-5. 신뢰 정책과 권한 정책
        => 신뢰 정책: 누가 역할을 사용할 수 있는가?
        => 권한 정책: 역할로 무엇을 할 수 있는가?
