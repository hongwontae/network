1. 데이터가 목적지 컴퓨터에 도달했을 떄 그 컴퓨터에서 실행 중인 어떤 프로그램이 데이터를 받아야 할까?
    => IP 주소만으로는 부족합니다.


2. 포트
    2-1. TCP 또는 UDP 통신에서 데이터를 받을 애플리케이션의 통신 끝점을 구분하는 번호입니다.
        => 192.168.1.10:80
        => ip 주소:포트 번호
        => OS는 IP주소, 프로토콜, 포트 등의 정보를 이용해 데이터를 적절한 소켓에게 전달합니다.
        => 일반적으로 소켓을 사용하는 프로그램이 데이터를 받습니다.
    
    2-2. 포트 번호의 범위
        => TCP와 UDP의 포트 번호는 각각 16비트입니다.
        => 0 ~ 65535 범위를 가질 수 있습니다.
    
    2-3. 자주 사용되는 포트 번호
        포트	대표적인 용도	전송 프로토콜
        22	    SSH	        TCP
        53	    DNS	        UDP / TCP
        80	    HTTP	    TCP
        443	    HTTPS	    TCP 또는 UDP(HTTP/3)
        3306	MySQL	    TCP


3. IP만으로 애플리케이션이 원하는 통신 방식 모두 제공하기 힘듭니다.
    => 패킷이 중간에서 사라지거나, 패킷이 보낸 순서와 다르게 도착하거나, 
        여러 패킷이 같은 목적지 컴퓨터의 서로 다른 프로그램으로 전달되어야 할 수 있습니다.
    =>이런 요구를 처리하기 위해 TCP와 UDP 같은 전송 계층(Transport Layer) 프로토콜을 사용합니다.


4. TCP (Transmission Control Protocol)
    4-1. 연결 지향적이며, 신뢰성 있는 바이트 스트림 통신을 제공하는 프로토콜입니다.
        => 데이터를 올바른 순서로, 빠짐없이 전달하도록 도와주는 프로토콜
        => 연결이 실패하거나 끊기면 최종 전달을 보장하지는 않습니다.
    
    4-2. TCP의 주요 특징
        1. 통신 전에 연결을 설정한다.
        2. 데이터가 손실되면 재전송할 수 있다.
        3. 데이터를 올바른 순서로 애플리케이션에 전달한다.
        4. 수신 측 처리 능력과 네트워크 혼잡 상황을 고려해 전송 속도를 조절한다.
    
    4-3. TCP의 연결 과정
        => TCP는 일반적으로 3-Way Handshake라는 과정으로 연결을 설정합니다.
        => SYN : 클라이언트가 연결을 요청합니다.
        => SYN + ACK : 서버가 요청에 응답하고 자신도 연결 설정을 요청합니다.
        => ACK : 클라이언트가 서버의 응답을 확인합니다.
        => 이 과정이 정상적으로 끝나면 TCP 연결이 설정되고 데이터를 주고받을 수 있습니다.
        => TCP는 웹 통신, SSH, 데이터베이스 연결 등에서 널리 사용됩니다.


5. UDP(ser Datagram Protocol)
    5-1. 연결 설정 없이 데이터그램을 전달하는 전송 프로토콜입니다.
        => 데이터 재전송, 순서 보장, 혼잡 제어 같은 기능이 없습니다.
    
    5-2. UDP는 TCP에 비해 프로토콜 구조가 단순하고 연결 설정에 드는 과정이 없습니다.

    5-3. 대표적인 사용 사례는 실시간 게임, 음성 통화, DNS 질의 등입니다.


6. TCP VS UDP
    구분	          TCP	          UDP
    연결 설정	       필요	            불필요
    데이터 전달 방식    바이트 스트림	    데이터그램
    순서 보장	       있음	            없음
    손실 시 재전송	    지원	         자체 지원 없음
    흐름·혼잡 제어	    지원	         자체 지원 없음
    헤더 크기	       최소 20바이트	  8바이트
    대표 사용 사례	    웹, SSH, DB	    게임, DNS, 실시간 통신
