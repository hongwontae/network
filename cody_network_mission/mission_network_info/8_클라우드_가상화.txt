1. 물리 서버
    1-1. 실제로 존재하는 하드웨어 컴퓨터를 의미합니다.
        => CPU, RAM, SSD/HDD, 네트워크 인터페이스, OS..
    1-2. 물리 서버에 Linux 설치, 웹 서버 프로그램 실행 -> 웹 사이트 운영 가능
        => 웹서비스가 CPU 2코어와 RAM 4GB 정도만 사용
        => 나머지 하드웨어 자원 남을 수 있음 
        => 이를 효율적으로 사용하기 위해 발전한 기술 중 하나가 가상화입니다.


2. 가상화
    2-1. 물리적인 컴퓨터 자원을 추상화해서 여러 개의 독립적인 
            컴퓨팅 환경처럼 사용할 수 있도록 만드는 기술입니다.
    
    2-2. 물리 서버 (cpu : 16코어, RAM : 64GB, SSD : 2TB)
        => 해당 서버를 여러 개의 가상 머신으로 나누어 사용 가능합니다.
        => CPU 16코어지만 가상 머신들이 각자 CPU를 가지고 있는 것처럼 동작합니다.


3. 하이퍼바이저
    3-1. 가상 머신을 생성하고 실행하며 물리 하드웨어 자원을 관리하는 소프트웨어 계층입니다.
    3-2. VM의 운영체제는 자신에게 CPU가 할당되어 있다고 인식하고 명령어를 실행합니다.
        => 하지만 실제 명령어는 결국 물리 CPU에서 실행합니다.
        => 하이퍼바이저와 호스트 시스템은 
            물리 CPU에서 각 VM의 가상 CPU가 실행될 시간을 스케줄링하고, 필요한 하드웨어 자원을 격리합니다.


4. 클라우드
    4-1. 클라우드 컴퓨팅은 인터넷 등의 네트워크를 통해 컴퓨팅 자원을 필요한 만큼 제공받아 사용하는 방식입니다.
        => 컴퓨팅 자원은 CPU, RAM, 저장장치, 네트워크 등..
    4-2. 웹사이트 운영 할 떄 두 가지 방식
        => 직접 물리 서버 운영
        => 클라우드 사용
    4-3. 클라우드의 특징
        => 자원을 빠르게 생성하거나 반납
        => 필요에 따라 규모를 조정
        => API 등을 통해 자동으로 관리


5. AWS EC2
    5-1. AWS에서 서버 컴퓨팅 자원을 제공하는 서비스입니다.
    5-2. 인스턴스
        => EC2에서 실행하는 서버 환경 하나를 EC2 인스턴스라고 합니다.
        => 일반적인 가상화 EC2 인스턴스는 하나의 가상 컴퓨터라고 생각하면 됩니다.
        => EC2를 생성할 때는 일반적으로 다음 사항들을 선택합니다.

        설정 항목	        의미
        AMI	              운영체제와 초기 소프트웨어 구성이 담긴 이미지
        인스턴스 유형	    사용할 vCPU, 메모리 등의 사양
        VPC 및 서브넷	    서버가 연결될 네트워크
        보안 그룹	        인바운드·아웃바운드 통신 허용 규칙
        키 페어	            SSH 등에 사용할 인증 키
        EBS 볼륨	        운영체제와 데이터를 저장할 블록 스토리지


6. 스토리지
    6-1. 데이터를 저장하는 자원 또는 시스템을 의미합니다.
        => 내 컴퓨터에서 SSD/HDD를 의미합니다.
    6-2. 클라우드에서는 저장장치가 반드시 EC2가 실행되는 물리 서버에 직접 장착되어 있을 필요가 없습니다.
        => AWS에는 여러 종류의 스토리지 서비스가 존재합니다.
    6-3. EBS(Elastic Block Store)
        => EC2 인스턴스에 연결해서 사용할 수 있는 블록 스토리지(Block Storage) 서비스
        => EC2 운영체제에서 디스크처럼 사용할 수 있는 저장 공간
        => EBS의 중요한 특징은 EC2 인스턴스의 실행 수명과 독립적으로 데이터를 보관할 수 있다는 것입니다.
        => EC2를 종료(Terminate)할 때 루트 EBS 볼륨이 자동 삭제되도록 설정되어 있다면 데이터가 삭제될 수 있습니다.
    
    6-4. S3(Simple Storage Service)
        => AWS의 객체 스토리지(Object Storage) 서비스
        => 데이터를 객체(Object)로 저장하고 API를 통해 접근하는 방식입니다.
    
    6-5. 인스턴스 스토어(Instance Store)
        => EC2 인스턴스는 물리 호스트에 연결된 임시 저장장치인 인스턴스 스토어도 제공합니다.
        => 빠른 임시 데이터 저장에 유용하지만, 인스턴스가 종료되거나
            특정 호스트가 교체되는 상황에서 데이터가 사라질 수 있습니다.
