1. IP 주소는 단순히 컴퓨터를 식별하는 숫자를 넘어서, 네트워크 부분과 호스트 부분으로 나누어 해석할 수 있습니다.


2. 192.168.1.10
    => IPv4는 총 32비트이고, 보통 8비트씩 네 부분으로 나누어 표현합니다.
    => 네트워크 부분은 24비트, 호스트 부분을 8비트
    => 네트워크 부분(Network Portion): 해당 IP가 어떤 네트워크에 속해 있는지 나타내는 부분
    => 호스트 부분(Host Portion): 해당 네트워크 안에서 특정 장치의 주소를 구분하는 부분
    => 92.168.1.10과 192.168.1.20은 둘 다 192.168.1.0/24 네트워크에 속할 수 있습니다.
    => 호스트란 IP 주소를 가지고 네트워크를 통해 통신하는 장치입니다.
    => 공유기에 연결된 컴퓨터 a, 컴퓨터 b, 스마트폰은 각각 ip 주소를 가지고 있습니다.
    => 컴퓨터 A의 IP 주소 -> 192.168.1.10/24 
        -> 앞의 24비트는 어느 네트워크에 속하는지, 뒤의 8비트는 그 네트워크 안에서 어느 주소인지


3. 서브넷 마스크
    3-1. 서브넷 마스크는 IPv4 주소의 어느 비트가 네트워크 부분이고, 어느 비트가 호스트 부분인지 구분하는 32비트 값입니다.

    3-2. IP 주소 : 192.168.1.10, 서브넷 마스크 : 255.255.255.0
        => 255을 이진수로 변환하면 1111 1111
        => 255.255.255.0을 이진수로 변환하면 11111111.11111111.11111111.00000000
        => 이 떄 서브넷 마스크 규칙은 1인 비트는 네트워크 부분, 0인 비트는 호스트 부분
        => 3-2의 서브넷 마스크는 앞의 24비트를 네트워크 부분으로, 뒤의 8비트를 호스트 부분으로 사용한다는 의미입니다.
    
    3-3. 컴퓨터는 IP 주소와 서브넷 마스크를 비트 AND 연산하여 네트워크 주소를 구할 수 있습니다.
        => IP 주소      1100 0000. 1010 1000. 0000 0001. 0000  1010
        => 서브넷 마스크  1111 1111. 1111 1111. 1111 1111. 0000  0000
        => AND 연산 결과 1100 0000. 1010  1000. 0000 0001. 0000  0000
        => 192.168.1.0
    
    3-4. 컴퓨터 A가 같은 네트워크에 존재하는 컴퓨터 B, 다른 네트워크인 서버에 데이터를 보내려고 할 떄
        => 컴퓨터 A는 목적지에 따라 데이터를 전달하는 방법을 결정해야 합니다.
        => 같은 로컬 네트워크에 있는 장치라면 직접 전달, 다른 네트워크에 있는 장치라면 일반적으로 라우터를 거쳐야 합니다.
        => IP 주소와 서브넷 마스크를 이용해서 같은 네트워크인지 판단
    


4. CIDR
    => IP 주소의 네트워크 크기를 유연하게 지정할 수 있도록 하는 주소 지정 방식입니다.
    => CIDR에서는 서브넷 마스크를 더 간단하게 표현할 수 있습니다.
    => IP 주소 : 192.168.1.10, 서브넷 마스크 : 255.255.255.0, CIDR 표기 : 192.168.1.10/24
    => /24는 앞에서부터 24비트가 네트워크 부분
    CIDR	서브넷 마스크	    호스트 비트
    /8	    255.0.0.0	     24비트
    /16	    255.255.0.0	     16비트
    /24	    255.255.255.0	 8비트
    /26	    255.255.255.192	 6비트
    /28	    255.255.255.240	 4비트

    4-1. 서브네팅 (네트워크 분할)
        => IPv4 주소는 32비트니까 네트워크 부분이 커질수록 호스트 부분은 작아집니다.
        => CIDR이 /24일 떄 네트워크 24비트/ 호스트 8비트 -> 일반적인 할당 가능 주소는 254개
        => CIDR이 /25일 떄 네트워크 25비트/ 호스트 7비트 -> 일반적인 할당 가능 주소는 126개
        => CIDR이 /26일 떄 네트워크 26비트/ 호스트 6비트..
        => 이렇게 네트워크 부분이 증가하면 기존 범위를 서로 다른 두 네트워크로 구분할 수 있게 됩니다.

        => /24 네트워크 하나를 /25 네트워크 두 개로 분할하면, 
            각각 126개의 호스트 IP 주소를 할당할 수 있는 네트워크 두 개가 만들어집니다.


5. 네트워크 부분은 정적인 값이고 호스트 부분은 동적인 값입니다.
    => 10.0.0.0/16 -> 앞에 16 bit가 네트워크 부분이고 여기로 접근하는 IP만 제대로 연결이 가능합니다.
    => 즉, 10.0.0.0 ~ 10.0.255.255이 허용 범위입니다. -> 즉, 호스트 부분만 바뀝니다.
