1. DNS (Domain Name System)
    1-1. 도메인 이름을 이용해 IP 주소 등의 정보를 조회할 수 있도록 하는 분산된 이름 시스템입니다.

    1-2. 예시
        => https://example.com
        => example.com은 도메인 이름입니다.
        => example.com처럼 기억하기 쉬운 이름을 사용하지만, 
                IP 네트워크에서 목적지로 패킷을 전달하려면 IP 주소가 필요합니다.
        => 컴퓨터가 DNS 정보가 이미 있는지 확인하고, 필요하면 DNS 리졸버에 질의합니다.
        => DNS 리졸버가 IP 주소를 찾아 응답합니다.
        => 컴퓨터가 얻은 IP 주소를 이용해 서버에 연결을 시도합니다.
        
    1-3. DNS가 ip 주소 찾아내는 방법
        => DNS는 전 세계 모든 도메인 정보를 하나의 서버에 저장하는 방식이 아닙니다.
        => 여러 DNS 서버가 역할을 나누어 정보를 관리합니다.
        => 루트 DNS 서버: 최상위 도메인(TLD)의 DNS 서버를 찾도록 도와줍니다.
        => TLD DNS 서버: .com, .net, .kr 등 최상위 도메인 아래의 권한 있는 DNS 서버를 찾도록 도와줍니다.
        => 권한 있는 DNS 서버(Authoritative DNS Server): 담당 도메인의 DNS 레코드에 대한 권한 있는 응답을 제공합니다.
        => 컴퓨터는 이 서버들에 직접 하나씩 질의하는 게 아니라, 재귀 DNS 리졸버에 조회를 맡깁니다.


2. HTTP (Hypertext Transfer Protocol)
    2-1. 클라이언트와 서버가 요청(Request)과 응답(Response)을 주고받기 위한 애플리케이션 계층 프로토콜입니다.
        => 웹 브라우저와 웹 서버 사이의 대표적인 통신 규칙입니다.
    
    2-2. HTTP 요청 구조
        GET /index.html HTTP/1.1
        Host: example.com
        Accept: text/html

    2-3. HTTP 응답 구조
        HTTP/1.1 200 OK
        Content-Type: text/html
        Content-Length: 39

        <html><body>Hello World</body></html>

    2-4. 일반적인 HTTP 통신은 암호화되지 않기 때문에 중간에서 데이터를 볼 수 있거나 변조할 위험이 있습니다.

3. HTTPS 
    3-1. HTTPS는 HTTP 통신을 TLS(Transport Layer Security)로 보호하는 방식입니다.
        => TLS는 통신 내용을 암호화하고, 전송 중 변조를 탐지하며, 인증서를 통해 서버의 신원을 검증하는 기능을 제공합니다.


4. HTTP/HTTPS는 TCP를 사용?
    4-1. 일반적인 HTTP/1.1과 HTTP/2 통신에서는 TCP를 사용합니다.
        => HTTPS라면 그 TCP 연결 위에 TLS를 적용
