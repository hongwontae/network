1. 인터넷 게이트웨이 (IGW)
    1-1. VPC와 인터넷 사이의 통신을 가능하게 하는 AWS 네트워크 구성 요소입니다.
        => Subnet의 주소에 EC2를 배치할 예정입니다.
        => 그리고 해당 EC2와 인터넷의 소통을 위해서 인터넷 게이트웨이가 필요합니다.
    
    1-2. 만든 VPC와 서브넷은 논리적으로 격리된 네트워크입니다.
        => 이 안에서는 10.0.0.0/16 범위의 사설 IP 주소를 사용할 수 있습니다.
        => VPC 내부에서 사용하는 사설 IP 주소만으로는 인터넷의 서버와 직접 통신할 수 없습니다.
    
    1-3. EC2 사설 IP: 10.0.1.10 가정
        => EC2가 구글 서버에 HTTP 요청을 보내려고 합니다.
        => 출발지 IP: 10.0.1.10 / 목적지 IP: 142.250.x.x (예시)
        => 인터넷의 라우터들은 10.0.1.10이라는 사설 IP로 응답을 전달할 수 없습니다.
        => 10.0.0.0/8은 사설 IP 주소 대역이고, 전 세계 수많은 독립된 네트워크가 동일한 주소를 사용할 수 있기 때문입니다.
        => 자신의 네트워크, 어떤 회사의 네트워크, aws vpc가 10.0.1.10으로 동일하다면 위 주소만으로 어디에
            응답을 보내야 하는지 구분할 수 없습니다.
        => 인터넷을 통해 통신하려면 외부에서 라우팅 가능한 공인 IP 주소가 필요합니다.

    1-4. Internet Gateway의 정체
        => VPC와 인터넷 사이에서 트래픽이 이동할 수 있는 경로를 제공합니다.
        => 퍼블릭 IPv4 주소가 있는 인스턴스의 사설 IPv4 주소와 퍼블릭 IPv4 주소 사이에서 1:1 주소 변환을 수행합니다.
            ->  인터넷 서버는 10.0.1.10이 아니라 3.35.100.20이라는 공인 IP를 출발지로 보게 됩니다.


2. AWS 인터넷 게이트웨이 생성 및 vpc 연결
    2-1. 인터넷 게이트웨이 생성 클릭
    2-2. 이름 -> cloud-mission-igw
    2-3. 생성된 igw 선택 -> 작업
    2-4. VPC 연결 클릭
    2-5. 생성해논 VPC와 연결


3. Internet Gateway를 VPC에 연결한다고 해서 서브넷이 즉시 인터넷에 연결되는 것은 아닙니다.
    => 라우팅 테이블에 규칙을 설정해야 합니다.
