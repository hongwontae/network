1. Subnet
    1-1. VPC의 주소 범위 중 일부를 떼어 만듭니다.
    1-2. 서브넷은 파티션처럼 논리적으로 나누는것과 비슷합니다.
    1-3. 10.0.0.0/16을 -> 10.0.1.0/24
        => 16개의 네트워크 부분을 24개로 바꾸면서 호스트 부분을 줄입니다.
        => 서브넷으로 나누면 네트워크 부분이 증가하고 호스트 부분이 감소합니다.

    서브넷  CIDR	  주소 범위	                전체 주소 수
    10.0.0.0/24	    10.0.0.0 ~ 10.0.0.255	256
    10.0.1.0/24	    10.0.1.0 ~ 10.0.1.255	256
    10.0.2.0/24	    10.0.2.0 ~ 10.0.2.255	256
    10.0.3.0/24	    10.0.3.0 ~ 10.0.3.255	256


2. Subnet으로 나누는 이유
    2-1. 웹 서버와 데이터베이스 서버가 있다고 가정
        => Public Subnet  10.0.1.0/24 -> EC2 웹 서버
        => Private Subnet 10.0.2.0/24 -> 데이터베이스 서버
        => 이렇게 나누면 각 서브넷에 다른 라우팅 테이블과 네트워크 ACL을 적용할 수 있습니다.


3. AWS Subnet 생성
    3-1. 서브넷 생성 클릭
    3-2. VPC ID에서 cloud-lab-vpc 선택
    3-3. 서브넷 이름 : cloud-lab-public-subnet
    3-4. IPv4 서브넷 CIDR 블록
        => 10.0.1.0/24
